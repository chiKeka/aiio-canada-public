# Remaining dependency security remediation

The prior lock reported nine high package entries propagated from `GHSA-vfj7-8cjw-p6xm` and four moderate entries from Drizzle's deprecated esbuild-kit loader. The current clean locked install reports zero findings in both `npm audit` and `npm audit --omit=dev`. No advisory, audit step or package functionality is suppressed. Both existing package chains remain usable, including shadcn's imported stylesheet and Sites' CommonJS transform.

## Bounded project-maintained patches

The [braces advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) still lists no released fix; registry latest is 3.0.3. `vendor/braces-depth-guard` retains its MIT license, upstream source hashes and exact unified patch, under distinct local identity `@aiio/braces-depth-guard@1.0.0`. A fixed 64 nesting limit covers brace/parenthesis parser containers and all recursive AST entry points. Iterative validation rejects excessive depth, node cycles and excessive traversal work before recursive code executes; expansion's parent loops are separately bounded. Legal parent/prev backreferences and 650 captured ordinary API results remain compatible. Deliberately deeper patterns now throw SyntaxError. This does not claim general combinatorial-expansion protection.

A 9,001-character nesting input reproduces `RangeError: Maximum call stack size exceeded` in the original 3.0.3 implementation; the installed fork rejects it before recursion. Eight tests cover this boundary, malicious direct ASTs, cycles, mixed containers, shared DAGs and normal range/escaping/options behavior.

`vendor/esbuild-kit-core-utils` preserves 3.3.2's compiled implementation and MIT license byte-for-byte, under local identity `@aiio/esm-core-utils-compatible@1.0.0`. Only package identity and its dependency change: vulnerable esbuild 0.18.20 is replaced by existing patched 0.25.12. This is a tested project compatibility patch, not an upstream-endorsed release. The implementation uses only `transformSync`, `transform` and `version`, not the server API affected by [the esbuild advisory](https://github.com/advisories/GHSA-67mh-4wv8-2f99). Seven tests verify executable CommonJS/ESM TypeScript, JSX, compiler options, dynamic-import interop, source maps and invalid-source rejection. Offline Drizzle generation produces identical SQL for all 13 tables before and after (SHA256 `51f5d67321a94f7ee7263f4656b7aacd8ff4bad83c5555cf561cb82e5b97a5a3`); no database was contacted or changed.

Root local dependencies plus npm `$dependency` overrides ensure every consumer resolves the actual fork. A clean `npm ci` was verified. No new registry versions were introduced: the graph removes original braces/core-utils and legacy esbuild binaries, while reusing already locked patched esbuild. Lockfile churn reflects resolution/layout changes, not broad package upgrades. Unsupported CLI downgrades and Drizzle major prereleases were rejected.

## Required gate and maintenance boundary

npm's advisory database does not cover local implementation bytes. `npm run test:dependency-security` therefore verifies complete fork file hashes, licenses, upstream provenance, installed package identities and actual resolution from every locked consumer. It rejects original vulnerable registry copies, missing global overrides and unexpected source drift. Isolated negative tests confirmed both source modification and override removal fail closed. Both quality and security workflows run this gate; the security workflow additionally runs full and production npm audits.

Application lint excludes unchanged third-party compiled loader distribution code and all installed node_modules. Patched braces sources remain linted with their required CommonJS syntax allowed; this is a module-style exception, not a security exception. Recursive node_modules are Git-ignored so local binary installation cannot be committed.

These forks require maintenance until a supported upstream fix/loader migration replaces them. Changes to their pinned source or package graph require a reviewed manifest update, regression tests and both build/browser paths. No risk acceptance, paid service, credentials, merge or production deployment was introduced. Empirical pilot validation remains blocked by missing project-level quantities and independent review, independently of this security remediation.
