# Conditional paired resource scheduler

The `schedulePackages` contract runs monthly paid-hour allocations by `region:trade`. Inputs are scenario packages with total hours, release month, planned finish, explicit predecessors and optional uncommitted remaining cost / separately incremental site overhead. It rejects missing predecessor IDs, cycles, invalid amounts and invalid capacity. A missing regional trade capacity stays unknown; it does not become measured zero supply. Distinct catchments never share capacity implicitly.

The selectable allocation contract supports pro-rata requested hours, protection of background commitments, and preferential DC allocation. Requests preserve each package's planned remaining window; unmet work carries forward, predecessor completion shifts dependent work, and service never exceeds monthly capacity. The reporting horizon can end with unfinished work: remaining hours are retained explicitly rather than silently discarded. Unknown or unfinished completion yields unknown timing and cost.

`pairedSchedule` runs the same background packages and capacity twice, with and without incremental DC packages. It reports differences for background packages only. Zero incremental DC produces zero incremental effects, including when supply is unknown. Explicit uncommitted exposure reprices by the ratio implied by the annual scenario index over the modelled shift. Optional site overhead is separately priced; neither entry can include the other's scope. Spent costs and fixed owner commitments must be excluded by the caller. Missing exposure stays unknown, not a fabricated measured zero.

The workspace uses an Alberta aggregate catchment and three aggregate trades as an uncalibrated fallback. It creates anonymous public cash-envelope packages once and optional annual other-private hours. Zero other-private hours means omitted coverage, not evidence of no private demand. Selected DC phases use the existing preliminary cost-to-hours assumptions and civil completion before electrical/mechanical work as an explicit enabling-work scenario. This is deliberately conservative and cannot represent a detailed observed critical path. Real packages can use the exported contract for distinct Calgary/Edmonton/rural catchments and named hospital, school, road or water outcomes; compatible package take-offs and contractor commitments are still required.

The workspace retains the planned demand screening rows separately from the constrained paired schedule. The JSON export contains both runs, monthly allocations/backlog, package completion dates, paired differences and the extended 120-month tail. No public package exposures or measured contractor capacity are provided by the existing evidence, so the workspace does not claim observed public costs or validated shortages. The user-entered delay illustration remains separately labelled.

Numerical acceptance tests cover hour conservation, capacity bounds, backlog carryover, package precedence, regional isolation, allocation policy, zero-DC differences, unknown capacity, unfinished tails, cycle rejection, private-demand pairing and escalation limited to explicit exposure.
